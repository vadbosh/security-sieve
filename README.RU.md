# security-sieve

Скилл ревью безопасности для Claude Code, Codex и Opencode, который **сообщает
только об уязвимостях, которые атакующий может использовать**. Проверяет код,
дифф ветки, конфигурацию инфраструктуры и код, который управляет ИИ-агентами.

Ревью идёт в два прохода:

1. **Поиск.** Ревьюер читает код и собирает кандидатов. У каждого указаны
   место, входные данные, опасная операция (sink) и что получает атакующий.
2. **Опровержение.** Каждого кандидата проверяют заново, по отдельности и в
   чистом контексте. Задача проверяющего — найти, почему это не уязвимость. Он
   формулирует утверждение одной фразой, проверяет каждое звено от входа до
   опасной операции и пишет сценарий атаки. Потом ставит оценку от 1 до 10.

Кандидат с оценкой 8 и выше попадает в отчёт как находка. С оценкой 5–7 — в
раздел «Needs verification», вместе с вопросом, ответ на который всё решит.
Всё, что ниже, отбрасывается и в отчёте не упоминается.

Зачем два прохода: ревьюеры — и люди, и модели — склонны видеть баги там, где
их нет, и завышать их серьёзность. Допустим, в отчёте три настоящие находки
среди двадцати правдоподобных. Читатель не может понять, какие три настоящие,
и такой отчёт стоит меньше, чем отчёт из одних этих трёх.

```
you:    /security-sieve
skill:  Diff mode: 14 files changed since merge base 3f2a91c.
        Tools found: semgrep, trufflehog. 9 candidates.
        Refutation: 2 findings, 1 needs verification, 6 dropped.
        ## Security review: feature/upload-api
        [VULN-001] Path traversal (High) — api/upload.py:48, CWE-22 …
```

## Что проверяет

| Запрос | Режим | Что происходит |
|---|---|---|
| «проверь мои изменения» или цель не названа внутри git-репозитория | Diff | Читает ветку относительно merge base. Сообщает о том, что изменение добавляет или делает достижимым. Старые проблемы идут в раздел «Outside the diff» и в оценку не входят |
| файл, каталог, репозиторий | Code | Начинает с точек входа (маршруты, обработчики, аргументы CLI, потребители очередей) и идёт по данным до опасных операций |
| модель угроз, «эксплуатируема ли эта CVE» | Threat model | STRIDE, поверхность атаки, разбор CVE и зависимостей |
| IAM, Kubernetes, Terraform, CI-пайплайны | Infrastructure | Гайд для этого вида конфигурации |

Гайды, которые скилл подгружает по типу файла:

- **Языки:** Python (Django, Flask, FastAPI), JavaScript и TypeScript (Node,
  Express, React, Vue, Next.js), PHP (Laravel, Symfony).
- **Инфраструктура:** Docker, Kubernetes и Helm, Terraform, CI/CD (GitHub
  Actions, GitLab CI, Jenkins), облачный IAM, секреты и mTLS.
- **Классы уязвимостей:** инъекции, XSS, авторизация, аутентификация,
  криптография, десериализация, работа с файлами, SSRF, CSRF, защита данных,
  дизайн API, бизнес-логика, ошибки конфигурации, обработка ошибок, цепочка
  поставок, журналирование.
- **ИИ-агенты:** инструменты с побочными эффектами, MCP-серверы и клиенты,
  скиллы, хуки и плагины.

## О чём не сообщает

Некоторые классы исключены целиком, какой бы ни была их серьёзность:

- отказ в обслуживании;
- отсутствие защитных настроек, если нет эксплойта;
- устаревшие библиотеки, если уязвимый вызов недостижим;
- теоретические гонки;
- подделка записей в логах;
- SSRF, при которой атакующий управляет только путём;
- пользовательский текст в промпте ИИ, если модель не может после этого
  добраться до инструмента с реальными побочными эффектами.

Переменные окружения и флаги CLI считаются доверенным входом.

Все исключения и прецеденты перечислены в SKILL.md: по ним видно, почему
кандидата отбросили.

## Данные сканеров

Скилл запускает сканеры, которые уже установлены: `semgrep`, `trufflehog`,
`gitleaks`, `osv-scanner`, `trivy`, `checkov`. Сам он ничего не ставит.
Срабатывание сканера — такой же кандидат, как остальные, и проходит
опровержение: большая часть вывода сканеров — советы по защите, а не эксплойты.

Два сканера ходят в сеть:

- `semgrep` скачивает правила из реестра Semgrep;
- `trufflehog` умеет отправлять каждый найденный ключ провайдеру, чтобы
  проверить, жив ли он. Скилл запускает его с `--no-verification` и спрашивает
  вас, прежде чем включить проверку.

## Что есть у каждой находки

- файл и строка;
- CWE и категория OWASP Top 10:2025;
- сценарий атаки: кто атакует, что отправляет, что происходит;
- оценка опровержения;
- исправление с кодом;
- варианты: тот же паттерн в других местах репозитория, проверенный так же.

В конце скилл ставит общую оценку защищённости от 1 до 10. Она считается по
фиксированным правилам: одинаковые находки всегда дают одинаковую оценку.

## Установка

```bash
git clone https://github.com/vadbosh/security-sieve.git
cd security-sieve
./install.sh --dry-run   # что будет записано
./install.sh
```

Установщик копирует `skills/security-sieve/` в каталог каждого найденного
ассистента: `~/.claude/skills`, `~/.config/opencode/skills`, `~/.codex/skills`.
Больше он ничего не пишет. Повторный запуск заменяет только изменившиеся файлы.

Установка в другой каталог:

```bash
./install.sh --skills-dir <path>
```

В ассистенте:

```
/security-sieve                  # текущая ветка относительно merge base
/security-sieve src/api/         # каталог
/security-sieve threat model of the upload service
```

Скилл срабатывает и на обычную просьбу сделать «security review».

### В Claude Code есть своя `/security-review`

В Claude Code встроена команда `/security-review`: она проверяет дифф ветки. У
этого скилла другое имя, поэтому встроенная команда остаётся доступной. Скилл
добавляет опровержение каждой находки, режим проверки кода, гайды по
инфраструктуре и агентам, данные сканеров.

## Откуда он взялся

Скилл начинался как `security-review` из
[getsentry/skills](https://github.com/getsentry/skills). Справочные материалы
в `references/`, `languages/python.md`, `languages/javascript.md` и
`infrastructure/docker.md` скопированы оттуда без изменений. Sentry написала их
на основе [OWASP Cheat Sheet Series](https://cheatsheetseries.owasp.org/).

В файле `UPSTREAM` закреплён коммит, из которого взяты копии, и записаны их
контрольные суммы. `./release.sh check` падает, если копия изменилась, а
`./release.sh upstream` сообщает, что у Sentry появились новые коммиты.

Проход опровержения и правила исключений повторяют подход
[anthropics/claude-code-security-review](https://github.com/anthropics/claude-code-security-review),
изложенный своими словами.

## Как присылать правки

Все проверки запускаются локально:

```bash
./release.sh check
```

Команда сверяет версию, журнал изменений, тег, индекс гайдов, лицензии, копии из
апстрима и установленные копии, а ещё ищет пути вашей машины в файлах, которые
уходят в поставку.

Новый гайд начинается со строки `<!-- SPDX-License-Identifier: Apache-2.0 -->`
и пишется своими словами. Тексты OWASP и Trail of Bits — под CC BY-SA 4.0:
ссылайтесь на них, не копируйте. Гайд попадает в поставку, только если его
называет таблица индекса в SKILL.md.
