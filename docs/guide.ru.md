# security-sieve: как это устроено

[English version](guide.en.md) · [README](../README.RU.md)

## Зачем два прохода

Ревьюеры — и люди, и модели — склонны видеть баги там, где их нет, и завышать
их серьёзность. Допустим, в отчёте три настоящие находки среди двадцати
правдоподобных. Читатель не может понять, какие три настоящие, и такой отчёт
стоит меньше, чем отчёт из одних этих трёх. Поэтому скилл разделяет поиск и
оценку:

1. **Поиск.** Собрать кандидатов. У каждого указаны место, входные данные,
   опасная операция (sink) и что получает атакующий.
2. **Опровержение.** Проверить каждого кандидата заново, по отдельности и в
   чистом контексте, с задачей доказать, что это не уязвимость.

## Режимы

| Запрос | Режим | Что происходит |
|---|---|---|
| «проверь мои изменения» или цель не названа внутри git-репозитория | Diff | Читает ветку относительно merge base (`origin/HEAD`, `main`, `master`, `trunk`, `develop`), плюс незакоммиченные и неотслеживаемые файлы. Сообщает о том, что изменение добавляет или делает достижимым. Старые проблемы идут в раздел «Outside the diff» и в оценку не входят. Если базу найти не удалось, скилл спрашивает, а не проверяет пустой диапазон |
| файл, каталог, репозиторий | Code | Начинает с точек входа (маршруты, обработчики, аргументы CLI, потребители очередей) и идёт по данным до опасных операций |
| модель угроз, «эксплуатируема ли эта CVE» | Threat model | STRIDE, поверхность атаки, разбор CVE и зависимостей |
| IAM, Kubernetes, Terraform, CI-пайплайны | Infrastructure | Гайд для этого вида конфигурации |

## Проход опровержения

Если ассистент умеет запускать подагентов, каждому кандидату достаётся свой
подагент, не больше пяти одновременно. Подагент видит только то, что ему
передали, поэтому он получает полным текстом:

- кандидата;
- шаг опровержения;
- весь раздел «Do not flag» из `SKILL.md`;
- гайды, загруженные для этого кода;
- что вернуть: утверждение одной фразой, сценарий атаки, оценку и исключение,
  если оно подходит.

Других кандидатов подагент не видит. Без подагентов скилл берёт кандидатов по
одному и для каждого заново читает код.

| Оценка | Итог |
|---|---|
| 8–10 | Находка, с серьёзностью |
| 5–7 | «Needs verification», с вопросом, ответ на который всё решит |
| 1–4 | Отбрасывается и не упоминается |

Для каждой подтверждённой находки скилл потом ищет тот же паттерн по всему
репозиторию; каждое совпадение проходит такое же опровержение.

## О чём скилл не сообщает

Следующие классы исключены целиком, какой бы ни была их серьёзность:

- отказ в обслуживании, исчерпание ресурсов, отсутствие лимитов запросов, ReDoS
  — в любом режиме; модель угроз может упомянуть угрозы доступности как
  заметки к дизайну;
- отсутствие защитных настроек без эксплойта: нет заголовка или флага,
  хранилище не зашифровано, нет lock-файла — пока у атакующего нет пути к
  данным;
- устаревшие библиотеки, если не показано, что уязвимый вызов достижим;
- теоретические гонки и атаки по времени;
- ошибки работы с памятью в языках, где память управляется безопасно;
- подделка записей в логах, отсутствие журнала аудита;
- SSRF, при которой атакующий управляет только путём;
- подстановка недоверенного текста в регулярное выражение;
- пользовательский текст в промпте ИИ, если модель не может после этого
  добраться до инструмента с реальными побочными эффектами;
- секреты на диске, которые и так защищены;
- сторонний код без пина — кроме случая, когда его владелец вне вашей
  организации **и** задача, которая его запускает, имеет секреты или права на
  деплой (тогда это находка уровня Medium).

Переменные окружения и флаги CLI считаются доверенными. Исключение — значения,
собранные из данных события, которыми управляет атакующий: например,
переменная CI из заголовка pull request.

Секрет в истории git — **это** находка, даже если в HEAD его уже нет: коммит
лежит в каждом клоне. Исправление начинается с ротации.

## Как запускаются сканеры

Скилл запускает только установленные сканеры, и любое их срабатывание для него
— кандидат. Большая часть вывода сканеров — советы по защите, а не эксплойты.

- Вывод пишется во временный каталог вне репозитория.
- В Claude Code сканеры работают в фоне, пока модель читает код. В Codex и
  Opencode они запускаются по очереди.
- Скилл читает выжимку: правило, файл, строку, коммит. `gitleaks` запускается
  с `--redact`. `trufflehog` печатает сам секрет в поле `Raw`, поэтому его
  вывод читается через `jq`, а без `jq` он пропускается. Значения секретов до
  модели не доходят, и утилита маскирования на машине не нужна.
- Сканеры секретов запускаются дважды: по истории git (режим `git`) и по
  рабочему дереву (режимы `filesystem` и `dir`). Режимы `git` не видят
  неотслеживаемые и подготовленные к коммиту файлы. В каталоге без git имеет
  смысл только второй запуск: `gitleaks git` там пишет «no leaks found», хотя
  просмотрел 0 коммитов.
- `checkov` запускается с `-o cli --compact`: его JSON для тех же находок
  примерно в семь раз больше.
- `trivy` и `checkov` запускаются без своих сканеров секретов. В выводе
  `trivy` были бы сами значения, а `checkov` только повторяет находки
  `trufflehog` и `gitleaks`.
- `semgrep` и `trivy` цитируют в JSON строки исходника, на которые сработали;
  скилл читает их вывод через фильтр `jq`, который эти цитаты выбрасывает, а
  без `jq` оба пропускает.

Сеть:

- `semgrep` скачивает правила из реестра Semgrep; без сети скилл продолжает
  без него;
- `trufflehog` запускается с `--no-verification`. Проверка отправила бы каждый
  найденный ключ провайдеру, поэтому скилл спрашивает, прежде чем её включить.

Команды сканеров написаны на bash. На Windows без Git for Windows bash нет:
Claude Code работает там через PowerShell. Тогда проверка базовая: модель
читает код, сканеры не запускаются. В отчёте стоит строка «Basic review: no
scanners (no bash shell)».

## Отчёт

Перед началом ревью скилл одним диалогом спрашивает, куда записать отчёт, в
каком формате и на каком языке:

| Вопрос | Варианты | По умолчанию |
|---|---|---|
| Куда | `~/security-reviews/<repo>-<date>.<ext>`; путь, который вы назовёте; только в чат | `~/security-reviews/…` |
| Формат | `md`; `txt` (обычный текст, 80 колонок); `html` (один файл, стили внутри, без скриптов и внешних ресурсов) | `md` |
| Язык | язык сессии; английский | язык сессии |

Внутрь проверяемого репозитория — только если вы так выберете: отчёт
перечисляет все слабые места, а в рабочей копии он в одном `git add -A` от
коммита. Подагент или запуск, где ответить некому, берёт значения по умолчанию
и пишет об этом в отчёте. Существующий отчёт не перезаписывается: если имя
занято, скилл выбирает другое, по которому отчёты различимы, — по области
проверки, времени или номеру. Пути, код, идентификаторы CWE и OWASP не
переводятся, и ни в одном формате нет значений секретов.

У каждой находки есть файл и строка, CWE, категория OWASP Top 10:2025,
сценарий атаки, оценка опровержения, исправление с кодом и варианты — тот же
паттерн в других местах репозитория. В сводке указана модель, которая делала
ревью, перечислены отработавшие инструменты и сказано, просканированы ли на
секреты история git и незакоммиченные файлы.

Общая оценка защищённости считается по формуле, поэтому одинаковые находки
всегда дают одинаковую оценку:

1. Есть находка Critical: `1`, если их две и больше или одна из них — живой
   секрет продакшена; иначе `2`.
2. Иначе `10 − 4 × High − 1.5 × Medium − 0.5 × Low`, с округлением вниз, но не
   ниже `3`.

Пункты «Needs verification» и находки вне изменений ветки не учитываются.

## Подробности установки

- Установщики пишут только в каталоги уже установленных ассистентов:
  `~/.claude/skills`, `~/.config/opencode/skills`, `~/.codex/skills` (на
  Windows — те же пути в профиле). `--skills-dir <path>` / `-SkillsDir <path>`
  ставит в другое место; пустое значение отклоняется.
- Повторный запуск заменяет только изменившиеся файлы. Файл, который вы
  правили вручную, сначала копируется в `~/.local/state/security-sieve-backups`
  (на Windows — в `%LOCALAPPDATA%`); хранятся три последние копии.
- Если в копии ассистента остался файл, которого в исходниках больше нет,
  установщик о нём сообщает, но не удаляет.
- Codex читает ещё и `~/.agents/skills`, а `~/.codex/skills` в его исходниках
  помечен как старый путь, оставленный для совместимости. Установщик пишет в
  `~/.codex/skills`, как и другие репозитории скиллов автора; чтобы поставить
  в новое место, запустите `./install.sh --skills-dir ~/.agents/skills`.
- Оба установщика предупреждают цветной рамкой, если нет `trufflehog`,
  `gitleaks` или `jq`. На Windows без bash `install.ps1` печатает
  предупреждение «BASIC REVIEW».

В Claude Code встроена команда `/security-review`, которая проверяет изменения
ветки. У этого скилла другое имя, поэтому встроенная команда остаётся
доступной.

## Лицензия и происхождение

Скилл начинался как `security-review` из
[getsentry/skills](https://github.com/getsentry/skills) (Apache-2.0).
Справочные материалы скопированы оттуда: 17 файлов в
`references/`, `languages/python.md`, `languages/javascript.md`,
`infrastructure/docker.md`. Отличается одна строка: шаблон grep в
`references/injection.md`, который GNU grep не принимал, — исправлен и записан
в `NOTICE`. Sentry написала их на основе
[OWASP Cheat Sheet Series](https://cheatsheetseries.owasp.org/), поэтому они
остаются под CC BY-SA 4.0. Их можно распространять и переделывать с указанием
авторства, а переделанная версия остаётся под той же лицензией.

Всё остальное — под Apache-2.0: `SKILL.md` (сделан на основе скилла Sentry,
с изменениями) и каждый гайд, первая строка которого —
`<!-- SPDX-License-Identifier: Apache-2.0 -->`. Проход опровержения и
список исключений следуют подходу
[anthropics/claude-code-security-review](https://github.com/anthropics/claude-code-security-review),
но изложены своими словами. Какой файл под какой лицензией — в
`skills/security-sieve/LICENSE`; авторство перечислено в `NOTICE`.

В `UPSTREAM` закреплён коммит, из которого взяты копии, и их контрольные
суммы. `./release.sh verify` падает, если копия изменилась, а
`./release.sh upstream` сообщает, появились ли у Sentry новые коммиты.

## Как присылать правки

```bash
./release.sh verify   # раздел журнала, индекс, лицензии, копии из апстрима, пути машины
./release.sh check    # verify + тег, HEAD и установленные копии, после тега релиза
```

Новый гайд начинается со строки `<!-- SPDX-License-Identifier: Apache-2.0 -->`
и пишется своими словами. Тексты OWASP и Trail of Bits — под CC BY-SA 4.0:
ссылайтесь на них, не копируйте. Гайд попадает в поставку, только если его
называет таблица индекса в `SKILL.md`.
